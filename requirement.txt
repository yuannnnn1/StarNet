AI Assignment #1 — CISC3024 Pattern Recognition
Codex Implementation Requirements

IMPORTANT:
- Do NOT reuse the previous MNIST + LeNet project as the assignment topic.
- Treat this as a new project from scratch.
- Do NOT assume a dataset, algorithm, application, architecture, or experiment in advance.
- The entire workflow must be AI-assisted. The student must NOT write any code manually.
- Codex is responsible for algorithm research, project design, implementation, experiments, result generation, verification, documentation, and report preparation.

============================================================
1. ASSIGNMENT OBJECTIVE
============================================================

The project must satisfy the original AI Assignment #1 requirement:

"Find a recent algorithm of Deep CNN or Deep Autoencoder with an application in computer vision and pattern recognition."

The project must therefore contain ALL of the following:

1. A genuinely recent algorithm/method.
2. The algorithm must belong to Deep CNN or Deep Autoencoder.
3. It must have a clear application in computer vision and/or pattern recognition.
4. The algorithm must be implementable and experimentally testable within the available local computing resources.
5. The algorithm must be supported by a credible primary research paper or official publication/source.
6. The implementation must be performed by AI/Codex rather than handwritten by the student.

Do NOT select:
- LeNet or other classical CNNs merely because they are easy to implement.
- A method only because it is famous.
- An algorithm that is not actually a Deep CNN or Deep Autoencoder.
- Vision Transformer/ViT as the main algorithm unless there is a clearly justified Deep CNN/Deep Autoencoder component that independently satisfies the assignment.
- An old algorithm presented as "recent" without evidence.

For "recent", prefer a method published in the 2020s and verify the publication year from the primary paper or an authoritative source.

============================================================
2. PHASE A — AI SEARCH FOR THE ALGORITHM
============================================================

Before writing implementation code, Codex must research candidate algorithms.

Search for multiple plausible recent Deep CNN / Deep Autoencoder methods and compare them using factual criteria:

- publication year
- original paper/source
- algorithm category
- main technical idea
- computer vision/pattern recognition application
- expected computational cost
- implementation complexity
- availability of reliable references
- suitability for a reproducible student project
- suitable public dataset(s)
- feasibility on the available machine

The final selection must be justified by evidence, not by simply calling one method "the best".

IMPORTANT:
- Record the actual AI research/search process.
- Record the actual prompts/questions used to search for the algorithm.
- Do NOT invent prompts retroactively.
- Keep useful search results, paper links, and reasoning because these will be needed in the final report.

Before implementation, provide a concise proposal containing:
1. selected algorithm
2. original paper
3. publication year
4. why it satisfies "recent Deep CNN or Deep Autoencoder"
5. computer vision/pattern recognition application
6. dataset
7. planned experiments
8. expected computational requirements
9. project directory/file plan

============================================================
3. PHASE B — SELECT A REALISTIC APPLICATION AND DATASET
============================================================

Choose an application in computer vision or pattern recognition that demonstrates the algorithm meaningfully.

Possible application types include, but are not limited to:
- image classification
- object recognition
- image reconstruction
- image denoising
- anomaly detection
- segmentation
- representation learning
- other clearly justified computer vision/pattern recognition tasks

Dataset requirements:
- Use a legitimate public dataset.
- Prefer a dataset with an official webpage or primary publication.
- The dataset must be appropriate for the selected algorithm and task.
- Document dataset source, size, classes/tasks, and train/validation/test protocol.
- Avoid unnecessarily large datasets if they make the project infeasible on local hardware.
- If the original dataset is too large for local execution, define a scientifically reasonable subset and clearly document the limitation.

Do not silently replace the selected algorithm with a simpler unrelated model just because the dataset is difficult.

============================================================
4. PHASE C — AI IMPLEMENTATION
============================================================

Codex must implement the complete project.

The student must NOT write any code manually.

Codex should:
1. Inspect the available workspace and hardware first.
2. Create or update the project structure.
3. Implement data loading and preprocessing.
4. Implement the selected algorithm.
5. Implement training.
6. Implement validation.
7. Implement testing/evaluation.
8. Implement result visualization.
9. Save reproducible experiment configurations and outputs.
10. Update/create README documentation.
11. Verify the complete workflow.

The implementation should stay faithful to the selected paper.

If an adaptation is necessary because of:
- image size,
- number of channels,
- dataset size,
- computational resources,
- number of classes,
- training budget,

then explicitly document the adaptation and explain why it is necessary.

Do not claim an exact reproduction if the implementation is an adaptation.

============================================================
6. EXPERIMENT REQUIREMENTS
============================================================

The project must include actual experiments, not only code.

At minimum, perform:

A. Main experiment
- Train the selected algorithm on the chosen task.
- Evaluate it on held-out test data.
- Report appropriate quantitative metrics.

B. Meaningful comparison or ablation
- Compare against at least one meaningful baseline, simplified version, ablation, or alternative configuration.
- Keep the comparison scientifically controlled where possible.
- Clearly state what is being changed and what is held constant.

C. Additional analysis
Include at least one useful analysis such as:
- confusion matrix
- qualitative predictions
- reconstruction examples
- error analysis
- robustness test
- ablation study
- parameter count
- training curves
- inference/training cost
- class-wise performance
- another task-appropriate analysis

Do not manufacture results.

All reported numerical results must come from actual executed experiments.

If an experiment cannot be completed, state the limitation instead of inventing a value.
